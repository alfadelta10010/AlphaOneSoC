**WO-46 c60b579 (PMA IO2 0x0C00_0000-0x0C3F_FFFF, IO1 default top 0x1003_FFFF): ACCEPT.** Data-only, LR->5,
SC/AMO->7, AMO allowed like IO0/IO1; closed = BASE FFFF_FFFF/TOP 0 (SoC default until WO-51). R6 is one-sided:
FC88 (term removed) and an IO1-top revert survive everything; a 4-cover core_req_cov (depth 14, 92 s) kills both
(S1). Latest hardens (q4x4-sb +0.277, q4x4-b +0.148 at max_ss) do NOT contain WO-46; worst paths are uio_out[1]
(QSPI) and soc.bus.d_addr[13]. WO-51 must add !d_addr[27] to clint_sel in the same commit that opens IO2.

**WO-49 6500370 (16550A): ACCEPT.** Linux-sequence probe 23/23 + smoke 154/154; CTI exactly 640 ticks. S1: BI/FE/RLS
persist until pop -> a datasheet ISR (IID 6 -> read LSR only) livelocks; fix = 1-flop err_ack. S2: tx_loadsz 16
stalls the CPU ~0.95 ms per burst (1,743 clk at div 1) with no RTS# -> recommend DT tx-threshold=<12>.
8250 facts: of_serial sets UPF_FIXED_TYPE (no autoconfig/loopback test); lsr_saved_flags merges out-of-band LSR
error bits into the next read_char; THRE test needs IRQ on both IIR reads; __stop_tx clears THRI.

**WO-47 d90baee (PLIC): ACCEPT-with-fixes.** S1 SPEC VIOLATION: claim uses elig incl. !thr; spec says claim is
not affected by threshold (polling with thr=max is a named use). WO's expected value encoded the error; Linux
unaffected (M-mode threshold always 0). Fix: cid from pend&en&prio; meip keeps thr. Driver: context needs parent
hwirq 11 in M-mode; EOI enables/completes/disables when en clear (complete-needs-en is right).
