RebelMikeRole icon, contributor — 11/13/24, 2:56 PM
On the controller side I have https://github.com/MichaelBell/tinyQV/blob/main/cpu/qspi_flash.v which is a relatively straightforward flash controller that uses quad data read commands but doesn’t assume continuous read mode. I don’t actually use it in tinyQV but Rej used it in the Atari 2600 project on tt09.

https://github.com/MichaelBell/tinyQV/blob/main/cpu/qspi_ctrl.v is the controller I actually use in TinyQV, which has the same assumptions as the QSPI sim I linked first. It supports configurable latency so I’m hoping it will run up to 40MHz or so on TT06 - we’ll find out soon!



Btw. the flash chip on the QSPI pmod has different versions of its datasheet, and several sites link to the one titled [W25Q128JV](https://www.winbond.com/hq/support/documentation/?__locale=en&category=%2F.categories%2Fresources%2Fdatasheet%2F&pno=W25Q128JV) that doesn't list all the modes available. There is another datasheet titled [W25Q128JV-DTR](https://www.winbond.com/hq/support/documentation/?__locale=en&category=%2F.categories%2Fresources%2Fdatasheet%2F&pno=W25Q128JV_DTR) that includes QPI & DTR modes. For designs that need faster random access from flash I recommend to use this extended version.
